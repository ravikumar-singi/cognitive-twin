## 3. Necessity and proportionality

- Only the claims needed for eligibility, regional rules and cohort views are requested from the IdP.
- Credentials use a random pseudonymous identifier, not a name.
- Credentials are based on answers only; no affect or biometric inference is used anywhere in phase one.
- Learners can download all their data at any time. Adults can delete their account themselves; a child's account is deleted by their teacher or school administrator, for example on a parent's request.
- Under-13s: first name only and no e-mail address; shorter stretches between breaks; the headband option is never shown to under-18s.

## 4. Risks and mitigations

| Risk | Likelihood / impact | Mitigation in the build |
|---|---|---|
| Unauthorised access to learner records | `[ ]` | Institution SSO; server-side role and cohort checks on every call; CSRF protection; rate limits; WAF; TLS 1.2+ only |
| Tampering with credentials | `[ ]` | Append-only ledger enforced by triggers and database permissions; hash chain checked at startup and nightly; alerts |
| Signing-key theft | `[ ]` | Keys held in KMS, sign-only IAM; rotation without invalidating old credentials; revocation |
| Data loss | `[ ]` | Multi-AZ PostgreSQL, point-in-time recovery, encrypted daily backups, restore tested |
| Automated decisions affecting learners | `[ ]` | Agents choose practice questions only; educators can see every decision and override issuance; the safety guardian's rules are logged |
| Profiling based on region | `[ ]` | Region only switches features off (e.g. affect inference in the EU); it never changes teaching quality |
| Re-identification from the ledger | `[ ]` | Random DIDs; no personal data in ledger rows; the link is destroyed on deletion |
